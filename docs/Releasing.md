# Releasing

## What it is

Every change that reaches the main branch goes out as a release: a version number, a change-log entry, a tag and a
zip on the project's GitHub releases page. There are no unreleased changes sitting on a machine; a studio someone runs
is always a release they can name, download again and roll back to.

## Expected outcome

- Anyone can install the latest studio from the releases page and read in CHANGELOG.md what changed and why.
- A version number names one exact tree: the tag, the zip and the running page's version agree.
- A release is checked on Linux and on Windows before it is public.

## Where the details are

Detailed instruction and information on numbering, the change log, the checks, tagging and the release files can be
found in docs/details/releasing-details.md.
